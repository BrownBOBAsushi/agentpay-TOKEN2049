# T-013 — Mandate signing page `/mandate` (CIP-30)
Milestone: M3 · Branch: feat/T-013-mandate · Status: todo
Depends on: T-011 merged. Live signing proof is SPIKE S3 (human with Lace or Eternl).

## Goal
The human writes their **Mandate** as a cheque and signs it with their own Cardano wallet. Output: the
Mandate bundle `{mandate, coseSign1, coseKey, payerAddress, digest}` (ARCHITECTURE step 1) to copy
into their agent. Mode: Operate — standard form controls and keyboard flow; the world lends type,
palette, the cheque layout, and the guilloche.

## Approach (decided — builder implements, does not re-decide)
- Client component page `app/mandate/page.tsx`. The form IS the cheque (T-011 `Cheque` in edit
  mode): payee line = text input; amount box = numeric input in human units with asset select
  (`tADA` → `lovelace`, 6 decimals; `tUSDM` → `TUSDM_UNIT` from `NEXT_PUBLIC_TUSDM_UNIT`, 6 decimals),
  converted to the atomic integer string exactly (no floats; string arithmetic); memo = purpose
  (1–280 chars); "Void after" = date-time input shown and stored as UTC → `expiry` unix seconds;
  nonce = 16 random bytes hex from `crypto.getRandomValues`, with a "new nonce" control;
  network fixed `cardano:preprod`, shown, not editable.
- Validate live with `parseMandate`; show each error next to its field in plain words (e.g. "Payee
  must be a preprod address (addr_test1…) or a Masumi agent identifier").
- The guilloche redraws from `mandateDigest` as fields change (debounce 150ms). Valid fields only.
- Wallet (CIP-30, no extra library): list `window.cardano` providers present among `lace`, `eternl`
  (show only installed ones; if none, say "Install Lace or Eternl to sign"). `enable()`, then
  `getNetworkId()` must be `0`, else refuse: "Switch your wallet to a testnet (preprod)". Payer =
  first of `getUsedAddresses()` or `getChangeAddress()`, hex → bech32 with `@evolution-sdk/evolution`
  `Address`; must be a key-hash payment credential (else explain).
- Sign: `api.signData(payerAddressHex, hex(utf8(jcs(mandate))))` → `{signature, key}`. Build the
  bundle, then run `verifyMandate(bundle)` in the browser before showing success. On `{ok:true}`:
  the signature hex prints on the signature line, the perforated SIGNED mark appears (ink), and two
  actions: "Copy bundle" (clipboard, confirms "Copied") and "Download bundle.json". On failure: show
  the reason code and what it means (e.g. SIG_INVALID with `hashed:true` → "This wallet signed a
  hashed payload; AgentPay Guard needs the raw payload"). Never claim success without `ok:true`.
- Wallet rejection or closed popup → "Signing cancelled", form keeps its values.
- No keys or seeds are ever requested or stored. Nothing is sent to a server.
- Craft floor and motion rules from T-011 apply; this page has no stamp animation.
