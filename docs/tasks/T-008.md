# T-008 — Paid Guard Task: Masumi seller flow
Milestone: M2 · Branch: feat/T-008-worker-paid · Status: todo
Depends on: T-007 merged. Live run needs the MPS runtime token (human, `docs/OPS.md`).

## Goal
Run a **Guard Check** as a paid **Task**: request signed seller terms from **MPS**, post
`masumiPayment` on the Task, wait for escrow `FundsLocked`, run the Guard Check, submit the result
hash, complete the Task, and later record the collection. Every step at most once.

## Approach (decided — builder implements, does not re-decide)
- API shapes, deadlines, and order: DEC-T09 exactly. Hashes: DEC-T10. Price: 1 tUSDM
  (`RequestedFunds:[{amount:"1000000", unit:TUSDM_UNIT}]`).
- `src/worker/mps.ts`: `createMpsClient({baseUrl, token, fetch})` with `createPayment(body)`,
  `resolve(blockchainIdentifier)`, `submitResult(blockchainIdentifier, hash)`. Header `token`,
  `redirect:"error"`, 30 s timeout, require `status:"success"`. Refuse a non-loopback / non-https
  base URL and `network` other than `Preprod`.
- `src/worker/paid-flow.ts`: stage machine stored in `task_journal`, each external call wrapped in
  `store.once({taskId, eventId:"-", action})`. Stages and actions:
  `start` (RUNNING) → `terms` (createPayment; `identifierFromPurchaser` = 10 random bytes hex,
  saved before the call) → `masumi-payment` (postEvent with `masumiPayment`; validate the payment as
  the demo's `purchasePayload` does: Preprod, Web3CardanoV2, one fund entry equal to the price,
  `sellerReturnAddress` null) → `await-escrow` (poll `resolve`; no side effect; continue only on
  confirmed `FundsLocked`; stop with a logged error after `payByTime`) → `check` (T-007
  `runGuardTask`; refuse to start if now ≥ `submitResultTime`) → `submit-result` → `await-result`
  (confirmed `ResultSubmitted` with matching hash) → `complete` (COMPLETED with the result) →
  `await-settlement` (Core `GET /v1/tasks/{id}/receipt`; store `settled`, `txHash`).
- Mode switch: `PAID_TASKS_ENABLED=true` env enables the paid flow for new Tasks; default stays free.
  A Task that started in one mode finishes in that mode (mode saved in the journal).
- Env (config.ts): `MPS_BASE_URL`, `MPS_RUNTIME_TOKEN`, `MASUMI_AGENT_IDENTIFIER`,
  `MASUMI_SUPPORTED_PAYMENT_SOURCE_INDEX` (integer), `TUSDM_UNIT`, `PAID_TASKS_ENABLED`.
  Add placeholders to `.env.example`. Never log the token or the result body.

## Files allowed
`src/worker/**`, `.env.example` (placeholders only).

## Acceptance criteria
- [ ] Fake MPS + fake Core tests: happy path posts in this exact order: RUNNING, createPayment,
      masumiPayment event, submit-result, COMPLETED; each exactly once.
- [ ] `submitResultHash` = sha256 of the exact COMPLETED comment bytes; `inputHash` = sha256 of the
      description.
- [ ] Restart at every stage boundary resumes without repeating any POST.
- [ ] Payment with wrong amount, unit, network, or non-null `sellerReturnAddress` → no masumiPayment post.
- [ ] Escrow never locks before `payByTime` → stops, no Guard Check run, no result submitted.
- [ ] `npm run typecheck && npm run lint && npm test` green.
- [ ] (orch + human, live, after merge) one paid Task: record Task ID, payment tx, result hash,
      collection tx in `docs/EVIDENCE.md`.
