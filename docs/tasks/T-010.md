# T-010 — Paid flow hardening from the first live run
Milestone: M2 · Branch: feat/T-010-paid-hardening · Status: todo
Depends on: T-008 + hotfix merged (81c2d76).

## Goal
Fix what the first live paid run showed (DEC-T13, `docs/EVIDENCE.md`), so the next paid **Task**
completes and failures can be diagnosed without manual probes.

## Approach (decided — builder implements, does not re-decide)
1. Deadlines (DEC-T13): offsets from env `PAID_PAY_BY_MINUTES` (20), `PAID_SUBMIT_RESULT_MINUTES` (60),
   `PAID_UNLOCK_MINUTES` (75), `PAID_DISPUTE_MINUTES` (90). Validate strictly increasing integers.
2. Escrow wait must not fail early: while now < `payByTime + 600 s`, keep polling. After that, stop
   only if MPS `onChainState` is still null; if MPS reports `FundsOrDatumInvalid` or another terminal
   state, stop with that state name in the journal.
3. MPS errors: an HTTP 400 from MPS on `POST /payment` creates nothing (proven live, MPS had 0
   payments) → throw `SafeToRetryError`. 401/5xx/timeouts stay uncertain. Keep the MPS JSON
   `error.message` (server text, no secrets) in the `WorkerError` message, truncated to 200 chars;
   never include request bodies or the token.
4. Logs: on a blocked Task print `blocked <taskId> <error.name>: <message>` (messages are sanitized).
   The live run needed a manual MPS probe to learn a 400 reason; this removes that.
5. Fixtures: add `src/worker/fixtures/mps-resolve-waiting.json` with the live pre-lock shape
   (`onChainState: null`, `NextAction.requestedAction: "WaitingForExternalAction"`,
   `CurrentTransaction: null`, `TransactionHistory: []`) and `mps-payment-400-seller-return.json`
   (`{status:"error", error:{message:"sellerReturnAddress must be …"}}`); use them in tests.

## Files allowed
`src/worker/**`, `.env.example` (placeholders only).

## Acceptance criteria
- [ ] Default offsets produce payBy/submitResult/unlock/dispute = +20/+60/+75/+90 min; invalid order rejected.
- [ ] Live-shape fixture keeps the Task in `await-escrow` until payBy + 600 s; then `failed` with reason.
- [ ] MPS 400 on createPayment → pending row removed, next poll retries; 500 → stays pending.
- [ ] Blocked log line includes error name and MPS message, and never the token (test asserts).
- [ ] `npm run typecheck && npm run lint && npm test` green.

## Out of scope
MPS settings (human), Railway (T-009).
