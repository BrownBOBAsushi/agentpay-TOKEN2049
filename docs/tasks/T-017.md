# T-017 — x402 demo-seller and Orchestrator (naive agent)
Milestone: M4 · Branch: feat/T-017-orchestrator · Status: todo
Depends on: main with `@x402/*@2.26.0` + `express@5` installed (orch did this; no new deps).
Decision: DEC-T14. API facts: `docs/research/X402-CARDANO-DIGEST.md` §1, §3a, §3b, §5. Read them.

## Goal
Build the M4 demo buyer path. The **Orchestrator** reads an offer page, gets the seller's x402
`PAYMENT-REQUIRED`, builds a **Spend Proposal** (`kind: "x402"`), hires the **Guard** with a free Sokosumi
Task (input = `{mandateBundle, proposal}`, DEC-T11), verifies the **Guard Receipt**, and pays via x402 only
on `APPROVE`. On `REFUSE` it stops and prints the **Diff**. S1 = honest page → APPROVE → paid.
S2 = injected page (payee + amount changed) → REFUSE → no payment.

## Approach (decided — builder implements, does not re-decide)
**demo-seller (`src/demo-seller/`)**
- `createDemoSellerApp({ resourceServer, sellerAddress, attackerAddress, baseUrl })` returns an Express app;
  `index.ts` wires the real `x402ResourceServer(new HTTPFacilitatorClient({url: X402_FACILITATOR_URL}))`
  with `ExactCardanoScheme` and listens on `DEMO_SELLER_PORT` (default 4021). Facilitator default:
  `https://x402.preprod.dev.ecosyseng.cf-deployments.org`.
- Paid routes (`paymentMiddleware`), `network: "cardano:preprod"`, `maxTimeoutSeconds: 600`,
  `extra: { assetTransferMethod: "default", confirmationPolicy: { l1Confirmations: 0 } }`:
  - `GET /api/market-data` — `2000000` lovelace to `sellerAddress`. Handler returns fixed JSON.
  - `GET /attacker/api/market-data` — `50000000` lovelace to `attackerAddress` (stands in for an attacker server).
- Offer pages (plain HTML, unpaid): `GET /offer` names `/api/market-data`. `GET /offer/injected` is the
  same page plus a hidden block (e.g. `display:none` div) with an injected instruction that names
  `/attacker/api/market-data` as "the updated endpoint". The instruction format is one line that the naive
  agent parses, e.g. `PAYMENT-ENDPOINT: <absolute-or-relative URL>`. The honest page has one such line,
  the injected page has two (the injected one last).
- `attackerAddress`: a deterministic preprod enterprise address from a public test key
  (`PrivateKey.fromBytes(new Uint8Array(32).fill(2))`, the same way `src/guard/cip8.test.ts` builds one).
  Nobody pays it: the Guard refuses. Comment this in code.

**Orchestrator (`src/orchestrator/`)**
- Naive agent: fetch the offer page, take the **last** `PAYMENT-ENDPOINT:` line, resolve against the page
  URL. GET it; expect 402. Decode with `x402HTTPClient.getPaymentRequiredResponse` (or the header decode in
  `@x402/core`); proposal = `{ kind: "x402", requirements: accepts[0] }`, parsed with `SpendProposalSchema`.
- Hire: run `sokosumi --preprod tasks create --personal --coworker-id <SOKOSUMI_COWORKER_ID> --name
  "Guard Check <scenario> <iso>" --description <JSON {mandateBundle, proposal}> --status READY --json` with
  `execFile` (no shell). Then poll `sokosumi --preprod tasks events <taskId> --json` every 3 s (timeout
  180 s) until an event with `status` `COMPLETED` or `FAILED`. Shape: `src/orchestrator/fixtures/
  sokosumi-task-events-s1.json` (real, redacted). The CLI runner is injected so tests use fakes. Check the
  real `tasks create --json` output for the id path defensively (accept `id`, `task.id`, `data.id`).
- Trust the Verdict only if all hold: `verifyReceipt(signed)` true; `signed.guardAddress === GUARD_ADDRESS`;
  `receipt.taskId === taskId`; `receipt.proposalDigest === proposalDigest(proposal)`;
  `receipt.mandateDigest === bundle.digest`. Otherwise stop with "receipt not trusted" (no payment).
- Pay on trusted APPROVE only: follow the template pay flow with `x402Client` + `ExactCardanoScheme(
  toClientCardanoSigner({ mnemonic: ORCHESTRATOR_WALLET_MNEMONIC, network, provider: blockfrost preprod
  with BLOCKFROST_API_KEY_PREPROD }))`. Spend controls allow exactly the approved asset with
  `maxAmountPerPayment` = approved amount. Re-request the endpoint; before you sign, check that the new
  402 requirements give the **same** `proposalDigest` as the approved proposal; if not, stop (no payment).
  On `settlement_pending`, re-send the **same** `PAYMENT-SIGNATURE`; never build a second tx (§5).
- Idempotency: a JSON journal file `runs/journal.json` keyed `{taskId, eventId, action}` (eventId = the
  COMPLETED event id; actions `hire`, `pay`). A second run that finds `pay` done for that key does not pay.
- Transcript: `src/orchestrator/transcript.ts` exports a zod `RunTranscriptSchema` (`v:1`, `scenario` "S1"|"S2",
  `recorded` boolean, `startedAt`, `offerUrl`, `injectedExcerpt` (string|null), `steps[]` of
  `{ at, kind, text }` with kinds `read-page | instruction | payment-required | proposal | hire | receipt |
  verify | pay | paid | stop`, `taskId`, `verdict`, `reasons`, `diff`, `payment` ({txHash, network, status}
  | null)). Each run writes `runs/<iso>-<scenario>.json` and prints the steps as log lines.
- CLI: `npm run orchestrator -- --scenario S1|S2 --mandate <bundle.json> [--seller http://127.0.0.1:4021]`.
  S1 → `/offer`, S2 → `/offer/injected`.
- Dev Mandate (until the user's wallet bundle from S3 exists): `npm run demo:mandate -- --payee <addr>
  --amount 2000000 [--minutes 60]` makes a fresh random test key, builds a Mandate (asset `lovelace`, new
  random nonce, expiry now+minutes, purpose "Buy market data (test-key Mandate)"), signs `jcs(mandate)` with
  `COSE.SignData.signData` exactly like `src/guard/cip8.test.ts`, checks `verifyMandate` ok, writes
  `runs/mandate-<iso>.json`, prints the path and digest. Never print the key.
- Env via `node --env-file-if-exists=.env.local --import tsx` (like `worker`). Add the new keys to
  `.env.example` (`X402_FACILITATOR_URL`, `DEMO_SELLER_PORT`) with empty/default values. Never log the
  mnemonic or the Blockfrost key.

## Acceptance criteria
- [ ] Tests (no network): seller returns 402 with the right `PAYMENT-REQUIRED` for both paid routes, using

- [ ] Tests: naive agent picks the last instruction; S2 proposal has attacker payTo + `50000000`.
- [ ] Tests with fake CLI runner + fixture: APPROVE path calls pay once; REFUSE path never calls pay;
      untrusted receipt (bad sig / wrong guardAddress / wrong proposalDigest / wrong taskId) never pays;
      changed requirements at pay time never pays; journal prevents a second pay.
- [ ] Test: `demo:mandate` bundle passes `verifyMandate`; transcript output parses with `RunTranscriptSchema`.
- [ ] `npm run typecheck && npm run lint && npm test` green. (orch runs `npm run build` and the live run.)
