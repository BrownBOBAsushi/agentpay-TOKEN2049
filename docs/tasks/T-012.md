# T-012 — Guard Receipt page `/receipt/[id]`
Milestone: M3 · Branch: feat/T-012-receipt · Status: todo
Depends on: T-011 merged (world, `Cheque`, `Stamp`, guilloche).

## Goal
A public, shareable page that proves one **Guard Check**: the signed **Mandate**, the presented
**Spend Proposal**, the **Verdict**, the field **Diff**, and the on-chain anchor. Mode: Read. Same
world as T-011 (`.impeccable/surfaces/app-page-tsx.md`); here it is a bank **return / clearing
advice** — one element gets total scale: the Diff.

## Approach (decided — builder implements, does not re-decide)
- Route `app/receipt/[id]/page.tsx`, server component, `revalidate = 60`. `id` is a Sokosumi Task ID.
  Special id `example` renders `public/examples/guard-receipt-refuse.json` (read only, never modified).
- Data (server only; never send keys to the client): Core `GET /v1/tasks/{id}` (description =
  `{mandateBundle, proposal}` per DEC-T11), `GET /v1/tasks/{id}/events` (COMPLETED comment = signed
  receipt JSON), `GET /v1/tasks/{id}/receipt` (settlement: `onChainState`, `settled`, `txHash`).
  Bearer `SOKOSUMI_COWORKER_API_KEY`, origin from `SOKOSUMI_API_URL` — reuse `src/worker/core.ts`
  client and its preprod-origin check. `GUARD_ADDRESS` env for `verifyReceipt`.
- Verify on the server with `verifyReceipt(signed, GUARD_ADDRESS)` and show the result plainly:
  "Guard signature valid — signed by addr_test1vq0v…" or "Signature INVALID" (never hide a failure).
  Show `receiptDigest`, `mandateDigest`, `proposalDigest` in OCR-B with copy buttons. A 64-zero
  digest renders as "unavailable" (DEC-T12).
- Layout top to bottom: Verdict stamp (RETURNED with reason codes, or perforated CLEARED) beside
  the Task ID and time; then **the Diff line at full width**: for each field, signed value over
  presented value, the differing presented value struck through with a margin mark "MUST NOT"
  in `--stamp`; matching fields set quiet in `--ink-2`. Then two small cheques side by side: the
  signed Mandate and the presented copy, each with its own guilloche (they differ when forged —
  that is the signature interaction). Then the anchor block: settlement state and, when a txHash
  exists, a Cardanoscan preprod link `https://preprod.cardanoscan.io/transaction/<hash>`; free
  rehearsal Tasks say "Free rehearsal — no payment".
- States: Task not found → "No Guard Receipt for this Task" + link home; Task not COMPLETED →
  "Guard Check in progress" with current status; COMPLETED comment not a receipt → "This Task's
  result is not a Guard Receipt". Core unreachable → say so; do not render stale guesses.
- `generateMetadata`: title "Guard Receipt — APPROVE|REFUSE · AgentPay Guard"; no secrets.
- Craft floor and motion rules from T-011 apply (stamp press is the only motion).

## Files allowed
