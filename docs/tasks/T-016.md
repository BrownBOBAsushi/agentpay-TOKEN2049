# T-016 — Receipt and Mandate pages on the teller's desk
Milestone: M3 · Branch: feat/T-016-desk-pages · Status: done
Depends on: T-015 merged (desk, paper objects, stub, rings, slip, paper clip).

## Goal
Replace the flat document layout of `/receipt/[id]` (the user's screenshot: a plain typed Diff list) and
`/mandate` with physical objects on the desk, keeping every T-012/T-013 behaviour and validity rule.

## Approach (decided — builder implements, does not re-decide)
**`/receipt/[id]`** (no change to data loading or `receiptValid` logic):
- Top on the desk: light legend "Guard Receipt", Task id and time (OCR-B, light), and the three plain
  facts (signature valid, matches Task, verdict) as short light lines.
- The scene: signed cheque (−1.2°) with the presented copy laid over it offset right/down (+2.5°).
  REFUSE: red-pencil rings around each differing field on the presented copy, the RETURNED stamp, and the
  RETURN ITEM slip clipped on, listing every Diff field as `field / signed / presented` rows and the
  reasons. APPROVE: the presented copy carries the perforated CLEARED mark; the slip is a "PAID — CLEARED"
  slip with the settlement state and Cardanoscan link. VOID: a VOID stamp in ink and a slip stating
  the failing fact; no CLEARED/RETURNED.
- Matching fields move onto the slip as a short "Checked" list with authored SVG tick marks.
- Digests and the on-chain anchor move onto a **ledger index card** (paper object, ruled lines, OCR-B
  values with copy buttons) below the scene.
- The field-by-field text stays available to screen readers in DOM order (slip content is real text).
- Mobile: cheques stack (presented below signed, no overlap), rings and slip stay attached.

**`/mandate`** (no change to signing logic or validation):
- The blank cheque lies on the desk with its stub; inputs stay standard controls inside the paper.
- The wallet panel becomes a small paper "teller's note" beside the cheque (same content and controls).
- After a verified signature: the SIGNED perforation appears on the cheque and on its stub; the
  Copy/Download actions sit on the desk below the cheque.

## Files allowed
`app/receipt/**`, `app/mandate/**`, `src/web/**` (presentation only; do not change `receipt-data.server.ts`
validity logic or `mandate-wallet.ts` signing logic). Not `public/examples/**`.

## Acceptance criteria
- [ ] All existing T-012/T-013 tests pass unchanged; add render tests for REFUSE/APPROVE/VOID scenes.
- [ ] `npm run typecheck && npm run lint && npm test && npm run build` green.
- [ ] Desk text ≥4.5:1; keyboard flow on `/mandate` unchanged (tab order test or note).

## Out of scope
New data, new validity rules, deploy.
