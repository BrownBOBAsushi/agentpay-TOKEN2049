# T-004 — x402 matcher, Diff, Verdict, guardCheck
Milestone: M1 · Branch: feat/T-004-x402-matcher · Status: done
Depends on: T-003 merged.

## Goal
Compare an x402 **Spend Proposal** to a verified **Mandate** field by field, and return a
**Verdict** (`APPROVE` | `REFUSE`) with reason codes and a **Diff**. This is the S1 (happy path)
and S2 (web page injection) demo logic.

## Approach (decided — builder implements, does not re-decide)
- `src/guard/proposal.ts`: zod `X402ProposalSchema = {kind:"x402", requirements}` where
  `requirements` is one entry of `accepts[]` from `PAYMENT-REQUIRED`
  (`docs/research/X402-CARDANO-DIGEST.md` §1: `scheme, network, amount, asset, payTo,
  maxTimeoutSeconds, extra`). `SpendProposal` is a discriminated union on `kind`; only `x402`
  now (`cardano-tx`, `masumi-purchase` come later).
- `src/guard/verdict.ts`: types
  - `ReasonCode` = `SIG_INVALID | SIGNER_MISMATCH | DIGEST_MISMATCH | BUNDLE_INVALID |
    MANDATE_EXPIRED | NONCE_REUSED | PROPOSAL_INVALID | NETWORK_MISMATCH | SCHEME_MISMATCH |
    PAYEE_MISMATCH | ASSET_MISMATCH | AMOUNT_MISMATCH | DEADLINE_AFTER_EXPIRY`
  - `DiffEntry = {field, signed, proposed}` (strings), `Verdict = {verdict, reasons, diff}`.
- `src/guard/match-x402.ts`: `matchX402(mandate, requirements, nowSec): {reasons, diff}`.
  Exact match (DEC-T06): `network` = mandate.network, `scheme` = `"exact"`,
  `payTo` = `payee`, `asset` = `asset`, `amount` = `amount` (string compare),
  deadline `nowSec + maxTimeoutSeconds` ≤ `expiry`. Collect **all** field mismatches into the
  Diff (do not stop at the first) so the demo shows payee AND amount changed.
- `src/guard/check.ts`: `guardCheck({bundle, proposal}, {nowSec, nonceUsed}): Verdict`.
  Order from `ARCHITECTURE.md` "Guard Check" step 4: verify (T-003) → stop on fail;
  expired → stop; `nonceUsed` → stop; parse proposal (fail → `PROPOSAL_INVALID`); match.
  `APPROVE` only when `reasons` is empty. Pure: `nowSec` and `nonceUsed` are inputs, no clock,
  no store, no network.

## Files allowed

## Acceptance criteria
- [ ] S1 test: proposal equal to the Mandate → `APPROVE`, empty Diff.
- [ ] S2 test: injected proposal with other `payTo` and higher `amount` → `REFUSE`,
      reasons include `PAYEE_MISMATCH` and `AMOUNT_MISMATCH`, Diff has both fields with
      signed and proposed values.
- [ ] Tests for: expired Mandate, `nonceUsed:true`, `cardano:mainnet` network, wrong asset,
      deadline after expiry, bad signature bundle (verify fails first, no match runs).
- [ ] `npm run typecheck && npm run lint && npm test` green.

## Out of scope
`cardano-tx` and `masumi-purchase` matchers, registry lookup, Receipt signing (T-005).
