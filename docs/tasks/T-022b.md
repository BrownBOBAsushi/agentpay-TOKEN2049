# T-022b — Wire live mode on `/store`: Buy → hire → APPROVE → pay on Cardano
Milestone: M4+ · Branch: feat/T-022b-wire (base 4103c38 = T-021 deployed + T-022a round 1) · Status: todo
Decision: DEC-T18. Card: T-022 (UI parts). Back end: T-022a (sol2 is changing its payment internals to a
durable Postgres claim in parallel — do not edit `src/web/store-payment.server.ts`,
`src/orchestrator/payment.ts`, `journal.ts`; keep calling the pay route by its HTTP contract).

## Goal
With `/store?live=<key>`, the presenter can run the whole real flow on one page: injection ON → Buy → hired
Guard REFUSE (as today); injection OFF → Buy → real x402 402 from `/api/store/latte` → Guard hired on Sokosumi
→ verified APPROVE → real payment of 6.5 tADA on Cardano preprod → tx hash + Cardanoscan link.

## Approach (decided)
- Client: read `live` from the URL once; if present show a small "LIVE" tag and a "Load signed Mandate
  (bundle.json)" file input; send the key as header `x-store-live-key` on hire, status and pay calls. Never
  render or log the key. Without a valid key everything stays public mode (exactly today's behaviour).
- Hire route (live + valid key, `hasStoreLiveKey`): (a) if a Mandate bundle was uploaded, validate it with
  `validateStoreMandate` and use it instead of the fixture; invalid → 400 with a clear message, nothing hired;
  (b) honest path: the server fetches this deployment's absolute `/api/store/latte` (derive origin from the
  request), decodes the 402 and uses `accepts[0]` as the proposal (the real x402 requirements); (c) hire the
  Guard for **APPROVE too** (live mode only). The status token must bind the Mandate digest actually used
  (uploaded or fixture); the status route must verify against the token's bound digest + the Task's own
  inputs (via `loadReceipt`), not against the fixture, in live mode.
- After a verified APPROVE in live mode, call `POST /api/store/pay` (contract in `app/api/store/pay/route.ts`)
  with the live key. If the pay route compares the Mandate to the fixture, adapt the **route/adapter layer
  only** so it uses the Mandate inside the hired Task (re-validated with `validateStoreMandate`).
- UI log lines: "402 PAYMENT-REQUIRED: 6.5 tADA to The Corner Store", "Guard hired on Sokosumi — Task …",
  "Signed Guard Receipt verified: APPROVE", "Paying over x402 on Cardano preprod…", "Paid: <tx hash>".
  Outcome: CLEARED scene + "Paid on Cardano preprod" with `https://preprod.cardanoscan.io/transaction/<hash>`,
  Sokosumi Task link, `/receipt/<taskId>`. Pay failure → honest message, no retry loop that could re-sign
  (the server owns idempotency).
- Public mode: unchanged (APPROVE local only, no pay).

## Files allowed
`app/store/**`, `app/api/store/hire/**`, `app/api/store/pay/route.ts` (adapter only), `src/web/store-*`
except `store-payment.server.ts`, `StoreClient*`, `docs/tasks/T-022b.build.md`.
