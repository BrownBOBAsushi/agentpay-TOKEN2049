# T-021 — `/store` one-line flow: hire the real Guard on Sokosumi
Milestone: M4+ · Branch: feat/T-021-store-hire · Status: todo · Base: release/m4-demo `9eacf7b`+this card
Decision: DEC-T17 (read it). Builds on T-020 (`/store`, `runStoreAgent`, `/api/store/check`).

## Goal
On `/store`, "Buy for 6.50 tADA" and "Send to my AI" both start one flow: the agent reads the page → builds
the proposal → **hires the real Guard on Sokosumi** → waits for the signed Receipt → shows the verdict scene
with links to the Task on Sokosumi and the public `/receipt/<taskId>`. No terminal, no screen change.

## Approach (decided)
- `POST /api/store/hire` `{injection}` (same zod as T-020): run `runStoreAgent`, then the local real
  `guardCheck` (as now). If the local verdict is **REFUSE** and hiring is configured and not rate-limited:
  create a Sokosumi Task and return `{mode:"hired", taskId, steps, proposal, local}` at once. Otherwise return
  `{mode:"local", ...}` (today's T-020 result) with a reason line ("APPROVE is not hired on the public page —
  one-time Mandate; see the recorded paid run" / "rate limit" / "not configured").
- Create Task: `POST {SOKOSUMI_API_URL}/v1/tasks` (check how `SOKOSUMI_API_URL` is used in
  `src/worker/core.ts` to avoid a double `/v1`), headers `Authorization: Bearer ${SOKOSUMI_COWORKER_API_KEY}`,
  `X-Context-User-Id: ${SOKOSUMI_TASK_USER_ID}`, body `{name:"Corner Store latte — Guard Check",
  description: JSON.stringify({mandateBundle, proposal}), assigneeId: SOKOSUMI_COWORKER_ID, status:"READY"}`.
  Response `data.id`. Real response shapes: `src/orchestrator/fixtures/sokosumi-task-events-s1.json`.
- `GET /api/store/hire/[taskId]`: reuse `loadReceipt` from `src/web/receipt-data.server.ts` (it already
  reads the Task events with the Coworker key and verifies the signed Receipt + input binding). Return
  `pending` until COMPLETED/FAILED, then the verified verdict, reasons, diff, `receiptValid`. Only accept
  task ids that this deployment created (keep an in-memory set; unknown id → 404) — the page must not
  become a proxy for any Task.
- Client: poll every 2 s, max 60 s. Log lines (ordered list): "Guard hired on Sokosumi — Task <id>",
  "Guard is checking…", "Signed Guard Receipt verified". Then the existing desk verdict, fed by the real
  Receipt. Links: "Open the Task on Sokosumi" → `https://preprod.sokosumi.com/tasks/<taskId>` (label: "your
  Sokosumi workspace (sign-in)"), and "Signed Receipt (public)" → `/receipt/<taskId>`. Timeout or FAILED →
  show the local verdict with an honest "Guard did not answer in 60 s" note.
- Rate limit (in-memory, per instance): ≥ 5 s between hires per client IP and ≤ 30 hires per hour total.
- Env (server only, never sent to the client): `SOKOSUMI_API_URL`, `SOKOSUMI_COWORKER_API_KEY`,
  `SOKOSUMI_COWORKER_ID`, `SOKOSUMI_TASK_USER_ID`, `GUARD_ADDRESS`. Add the new names to `.env.example`.
  Missing env → `mode:"local"`.
- Copy: keep "The agent is scripted… No money moves here."; add "The Guard runs as a Coworker on Sokosumi."
