first in the 3-minute video: one signed cheque, then the agent's forged copy coming back RETURNED.
Use `CONTEXT.md` words: **Mandate**, **Spend Proposal**, **Guard Check**, **Verdict**, **Diff**,
**Guard Receipt**.

## Approach (decided — builder implements, does not re-decide)
**Tokens** (`app/globals.css`, CSS custom properties): `--paper #e4ecef`, `--guilloche #9db7c2`,
`--ink #16303a`, `--ink-2` = a tint of ink with ≥4.5:1 on paper (compute; never plain grey),
`--stamp #b3261e` (REFUSE marks only, never decoration). Light only (scene: paper on a desk, video).
Theme the browser surfaces: `::selection` (guilloche bg, ink text), caret, focus ring (2px ink, 3px
offset), scrollbar, link underline offset, `font-variant-numeric: tabular-nums` on all values.

**Fonts** — self-hosted with `next/font/local` from `app/fonts/` (no network fetch at build):
Marcellus SC (`MarcellusSC-Regular.ttf`) for printed legends and the amount box; Schibsted Grotesk
(`SchibstedGrotesk-VF.ttf`, italic file too) for prose and controls; OCR-B (`OCRB-10.otf`) for every
value, address, digest, hash, and the MICR line — **never above 28px** (auto-converted outlines).
Display max 6rem, tracking floor −0.04em, prose measure 65–75ch, more space above headings than below.

**Components** (`src/web/`, React server components unless they need state):
- `guilloche.ts` — pure function `guillochePaths(digestHex: string, opts) → string[]` (SVG path
  data). Deterministic: the digest bytes seed rosette parameters (lobes, radii, phase, line count).
  Same digest → identical paths; one changed byte → visibly different pattern. Unit-test both.
- `Cheque.tsx` — the Mandate drawn as a cheque: printed legend line, "Pay to the order of" payee
  line, amount box, memo line (purpose), "Void after" expiry (UTC), signature line showing the
  CIP-8 `coseSign1` hex (OCR-B, truncated middle with the full value in a copy button and `title`),
  MICR-style bottom line `⟨nonce⟩ ⟨digest first 8…last 8⟩ ⟨amount⟩` using authored SVG separator
  symbols (not Unicode glyphs). Guilloche field from the Mandate Digest behind it.
- `Stamp.tsx` — authored SVG rubber stamp: double-rule box, text "RETURNED", reason codes on a
  second line; ink texture via `feTurbulence` + `feDisplacementMap`, rotated −6°, `--stamp` colour.
  Variant `cleared`: perforated "CLEARED" made of punched circles in ink (approval is a mark, not green).
- Icons only as authored SVG in one stroke weight. No emoji, no Unicode icons, no icon fonts.

**Landing `/`**:
1. First viewport = the contract's FIRST VIEWPORT: one full-width cheque (≈2.35:1 desktop; on
   mobile the cheque stacks its lines vertically, never scales text below 14px). Legend "AgentPay
   Guard" + display line "An agent can only spend what its human signed." Real values from
   `src/web/fixtures/landing-s2.json` (committed: a real preprod Mandate bundle signed with a test
   key, plus the injected proposal). Under the signature line, small honest label:
   "Signed with a test key on Cardano preprod". Actions on the cheque: primary link "Sign a
   Mandate" → `/mandate`; secondary link "Read a real refusal" → `/receipt/01a10ff9-5009-73d6-903e-7a5effdb30d0`.
2. Second screen: the agent's presented copy — same cheque layout, payee and amount from the
   injected proposal, the changed values struck through on top of the signed ones; the RETURNED
   stamp with `PAYEE_MISMATCH · AMOUNT_MISMATCH`. Run `guardCheck` at build time on the fixture so
   the reasons shown are computed, not typed. Input shape: `guardCheck({ bundle: fx.mandateBundle,
   proposal: fx.proposal }, { nowSec, nonceUsed: false })` (the fixture uses the DEC-T11 Task
   description keys). The fixture's Mandate expires 2027-01-01 UTC, so build-time checks stay valid;
   orch verified: injected → REFUSE [PAYEE_MISMATCH, AMOUNT_MISMATCH]; matching → APPROVE.
3. Third screen: "the back of the cheque" — three endorsement stamps in order (sequence carries
   meaning, so numbering is allowed): Signed by the human's wallet (CIP-8) → Presented by the agent
   as an x402 payment → Cleared or returned by the Guard, Receipt hash anchored on Cardano, with a
   link to the real result tx on `https://preprod.cardanoscan.io/transaction/a3609fa45c44de6a85e8d1bec40d0d6844da5129e25f5ee27ac0c7c9747f5c32`.
4. Footer: "Cardano preprod · test funds only", link to `docs`-free GitHub repo URL from env
   `NEXT_PUBLIC_REPO_URL` and Sokosumi listing from `NEXT_PUBLIC_SOKOSUMI_LISTING_URL`; render
   each link only when its env is set (do not invent URLs).

**Motion** — one authored moment only: the RETURNED stamp presses when its cheque enters the
viewport (IntersectionObserver): from scale 1.12, rotate −9°, `blur(3px)`, opacity 0 → scale 1,
rotate −6°, blur 0, 420ms `cubic-bezier(0.16,1,0.3,1)`, with ink spread (`feMorphology` radius 0→0.6).
`prefers-reduced-motion`: render the final stamp, no animation. Nothing else animates.

**Refuse** (craft floor): no kicker/eyebrow labels above headings, no same-size card grids, no
hero-metric block, no gradient text, no glass/blur decoration, no coloured side borders >1px, no
hard offset shadows, no monospace as costume (OCR-B is for values only), no shield/padlock imagery.
