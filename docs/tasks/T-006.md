# T-006 — Idempotency store and Mandate nonce store (Postgres)
Milestone: M2 · Branch: feat/T-006-store · Status: todo
Depends on: T-005 merged.

## Goal
Make every Worker side effect run at most once, keyed by `{taskId, eventId, action}` (CLAUDE.md
hard rule), and record which Mandate nonces an `APPROVE` consumed (DEC-T11). A restart must never
run a Task twice, post `masumiPayment` twice, or submit a result twice.

## Approach (decided — builder implements, does not re-decide)
- Packages (orch installs them): `pg`, `@types/pg` (runtime), `@electric-sql/pglite` (dev, tests only).
- `src/worker/db.ts`: a tiny `Db` interface `{query<T>(text, params): Promise<{rows: T[]}>}`.
  `createPgDb(databaseUrl)` wraps a `pg.Pool`; tests wrap PGlite. No ORM.
- `src/worker/migrate.ts`: idempotent SQL (`CREATE TABLE IF NOT EXISTS`), run at Worker start:
  - `side_effect(task_id text, event_id text, action text, status text check (status in ('pending','done')),
    result jsonb, created_at timestamptz default now(), updated_at timestamptz default now(),
    primary key (task_id, event_id, action))`
  - `mandate_nonce(payer text, nonce text, task_id text not null, created_at timestamptz default now(),
    primary key (payer, nonce))`
  - `task_journal(task_id text primary key, stage text not null, data jsonb not null, updated_at timestamptz default now())`
- `src/worker/store.ts`:
  - `once<T>(key, fn): Promise<T>`: `INSERT … ON CONFLICT DO NOTHING` a `pending` row. If inserted,
    run `fn`, then set `done` + `result`. If the row exists and is `done`, return its `result`
    without calling `fn`. If it exists and is `pending`, throw `UncertainSideEffectError` (a crash
    happened mid-call; no automatic retry, same rule as the demo's `-pending` stages, DEC-T09).
    If `fn` throws, delete the `pending` row only when the error is a `SafeToRetryError`
    (a subclass the caller uses for failures known to have no effect, e.g. HTTP 4xx before send);
    otherwise leave it `pending`.
  - `isNonceUsed(payer, nonce, taskId)`: true only when a row exists with a *different* task_id.
  - `consumeNonce(payer, nonce, taskId)`: insert; on conflict with a different task_id return
    `false` (caller turns the Verdict into REFUSE `NONCE_REUSED`); same task_id returns `true`.
  - `readJournal(taskId)` / `writeJournal(taskId, stage, data)`.
- Do not log `result` contents or any env value.

## Files allowed
`src/worker/db.ts`, `src/worker/migrate.ts`, `src/worker/store.ts`, `src/worker/*.test.ts`,
`package.json`, `package-lock.json`.

## Acceptance criteria
- [ ] PGlite tests: `once` runs `fn` once across two calls; returns the stored result on the second.
- [ ] A `pending` row (simulated crash) makes `once` throw `UncertainSideEffectError` and not call `fn`.
- [ ] `SafeToRetryError` removes the pending row; any other error keeps it.
- [ ] Two concurrent `once` calls with the same key call `fn` exactly once.
- [ ] Nonce: consume by task A → `isNonceUsed(…, A)` false, `(…, B)` true; `consumeNonce(…, B)` false.
- [ ] Migration runs twice without error.
- [ ] `npm run typecheck && npm run lint && npm test` green.

## Out of scope
Sokosumi/MPS calls (T-007, T-008), connection to a real Postgres (orch checks it at T-007 run).
