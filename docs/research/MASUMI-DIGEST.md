## 0. READ THIS FIRST: two paths, and the hackathon one differs from the local skill

The local skill describes the classic path: self-hosted MIP-003 HTTP service (FastAPI/Express) + Payment Service on :3001 + registry NFT + Tally form listing. The hackathon guide [GUIDE]/[T49] describes a newer **Coworker path**: a Sokosumi Coworker driven by the `sokosumi` CLI, with a **polling worker** (no public URL required initially) and Payment Service (MPS) on **:3012** using `Web3CardanoV2` payment source. The two differ in port, Node/pnpm versions, payment source version, and how Sokosumi reaches your agent. **Follow the hackathon path for the submission; use the skill for API reference and MIP-003/registry detail.** The organisers' prompt language is JavaScript/TypeScript (Node 24+, Vercel `eve` agent, CLI) [T49 "Key Technical Assumptions"].

## 1. End-to-end Coworker checklist (hackathon path)

Hosted by others: Sokosumi preprod (web app, API, credits/Stripe test mode), Masumi Dispenser, Blockfrost, Cardano preprod, model provider (Z.ai or any). Self-run: your worker, your agent (eve), **your own MPS node + PostgreSQL** (there is no hosted preprod payment host: [SKILL] masumi-payments.md "Base URLs"; [GUIDE] "Do not deploy locally; host eve and MPS for judge access" so host on Railway/similar: [T49] "Deployment Path").

7. **Fund wallets**: https://dispenser.masumi.network gives test ADA and USDM; requires a verification code from your registration email and a receiver address; 5 ADA collateral arrives in a separate second tx [dispenser page fetched]. (Skill also lists https://faucet.masumi.network [SKILL SKILL.md "Tools"]; treat dispenser as canonical for this event.)

Save `agentIdentifier`, `policyId`, `smartContractAddress`, `sellerVkey`, `sellerAddress`. Create a scoped MPS runtime key (`ReadAndPay`, Preprod, selling wallet only).

10. **Credits for Task creation**: switch to Personal Workspace, https://preprod.sokosumi.com/billing?tab=credits , Stripe test card 4242 4242 4242 4242, any future expiry/CVC [GUIDE]. Sokosumi credits fund the Task; model fees are separate [GUIDE].
11. **Paid task**: `sokosumi --preprod tasks create --personal --coworker-id ID --name "Paid demo" --description "..." --status READY --json`. ## 2. How Sokosumi talks to your agent

**Coworker (hackathon path): pull model.** Worker polls `GET /coworkers/me/events` (Bearer coworker key), inspects Task, posts progress `POST /tasks/{id}/events` (statuses `RUNNING`, `INPUT_REQUIRED`, `COMPLETED`, `FAILED`), reports credit usage `POST /coworkers/me/usage` with stable idempotency keys like `usage:{taskId}:{eventId}:{action}` [CW]. Capabilities `chat` (needs `baseURL`, OpenAI-Responses-compatible API) and/or `tasks` (needs a running worker). Access gate: not archived, whitelisted, capability present [CW][SKILL sokosumi-api-reference.md]. Remote upstreams receive `X-Delegation-User-Id` / `X-Delegation-Organization-Id` headers [CW]. CLI also exposes `runtime start|complete` which is what the guide's rehearsal uses [GUIDE].

**Classic MIP-003 agents: push model (Sokosumi/buyers call your server).** Marketplace job `POST /agents/{id}/jobs` with `{inputSchema, inputData, maxCredits, name}`; job status enum `started, processing, input_required, result_pending, completed, failed, payment_pending, payment_failed, refund_pending, refund_resolved, dispute_pending, dispute_resolved` [SKILL sokosumi-api-reference.md]. That Sokosumi calls your MIP-003 `/start_job` is MY-INFERENCE from the skill's "Prereqs: MIP-003 API compliant" [SKILL sokosumi-marketplace.md]; the exact call sequence was not documented.

### MIP-003 endpoints (needed only for the classic/buyer-callable path)
Per [MIP3] and [SKILL agentic-services.md]: `POST /start_job`, `GET /status?job_id=`, `GET /availability`, `GET /input_schema` required; `POST /provide_input`, `GET /demo` optional.
- **MIP-003 spec** statuses: `awaiting_payment, awaiting_input, running, completed, failed`; `/start_job` request `{identifier_from_purchaser, input_data:{...object...}}`; response includes `id, blockchainIdentifier, payByTime, submitResultTime, unlockTime, externalDisputeUnlockTime, agentIdentifier, sellerVKey, identifierFromPurchaser, input_hash` [MIP3].
- **Skill version differs**: `input_data` as `[{key,value}]` array; response `job_id, blockchain_identifier, payment_address, amount_lovelace`; statuses add `pending`, `refunded`; completed returns `output, input_hash, output_hash` [SKILL agentic-services.md]. The skill's shapes look older/SDK-specific; verify against live `pip-masumi` before relying on them.
- `input_schema`: MIP-003 allows `input_data` or `input_groups` (not both); each field `{id, type: string|number|boolean|option|none, name?, data?, validations?}` [MIP3]. Sokosumi's richer type list (text, textarea, email, url, file, radio, multiselect, ...) is in [SKILL sokosumi-api-reference.md].
- Errors: 400, 404 (`JOB_NOT_FOUND`), 500 [MIP3][SKILL].

## 3. Seller payment flow

Classic [SKILL masumi-payments.md "Seller Flow"]: `POST /registry` -> buyer hits `/start_job` -> seller `POST /payment` (body `network, agentIdentifier (>=57 chars), inputHash, identifierFromPurchaser`, optional `RequestedFunds, payByTime, submitResultTime`) returns `blockchainIdentifier` + pay address -> buyer locks USDM in contract -> node polls chain ~20s, `GET /payment` state `FundsLocked` -> run job -> `POST /payment/submit-result {network, blockchainIdentifier, submitResultHash}` (<=250 chars) state `ResultSubmitted` -> dispute window `unlockTime` -> auto-collect (`AUTO_WITHDRAW_PAYMENTS=true`): 95% seller, 5% Masumi fee in USDM.
Hackathon variant adds: signed seller terms and posting `masumiPayment` into the Sokosumi Task event so that Sokosumi Core's buyer funds escrow ("Core's buyer funds escrow; your local purchasing wallet does not replace that in the normal flow") [GUIDE]. **The exact JSON of `masumiPayment` and the "signed seller terms" API call were NOT in any fetched doc.** Get them from `mps-openapi.json` (`/api-docs`), `sokosumi skills`, and the demo repo https://github.com/masumi-network/demo-agent-token2049 (branch with Hackathon Team Name Finder; README body was not fetchable).
- Hashing (MIP-004) [SKILL agentic-services.md][MIP-004 title only on GitHub]: `inputHash = sha256("{identifierFromPurchaser};{RFC8785-canonical input}")`, `outputHash = sha256("{identifierFromPurchaser};{output}")`, `submitResultHash = inputHash + outputHash` (128 hex). Field names old docs used (`identifier`, `decisionHash`) are wrong.
- Timers (registry defaults) [SKILL registry-identity.md]: `averageExecutionTime 60s`, `submitResultTime 120s`, `unlockTime 3600s`, `refundTime 7200s`.
- Contract redeemers [SKILL smart-contracts.md, "simplified/conceptual"]: SubmitResult, WithdrawPayment (after unlock, 95/5), RequestRefund, AuthorizeRefund, WithdrawRefund, AdminResolve.
- Fees: seller ~0.5 ADA submit + ~0.8 ADA collect + 5% USDM; buyer ~0.5 ADA [SKILL masumi-payments.md].
- Other MPS endpoints: `/payment/x402`, `/webhooks`, `/payment/diff/next-action`, `/payment/error-state-recovery`, `/payment/resolve-blockchain-identifier`, `/payment-source`, `/wallet`, swaps ADA<->USDM [SKILL masumi-payments.md "Complete Endpoint Index"]. MPS docs folder also has `webhook-events.md`, `x402.md`, `security.md` [MPS /docs listing].

## 4. BUYER flow (agent hires and pays another agent)

Primary API (MPS, self-run or managed): [SKILL masumi-payments.md "Buyer Flow"]
1. Discover: `POST $REGISTRY_SERVICE_URL/registry-entry-search/` `{network, query, filter, limit}` (token header).
2. `POST {agent.apiBaseUrl}/start_job {input_data, identifier_from_purchaser}` -> seller returns `blockchain_identifier` (+ terms).
3. Lock funds: `POST $PAY/purchase {network, blockchainIdentifier, ...}`. The skill's snippet says "(additional fields per /docs)": **full purchase body not documented in the skill; read live OpenAPI.** MIP-003 start response carries `payByTime, submitResultTime, unlockTime, externalDisputeUnlockTime, sellerVKey, agentIdentifier, input_hash`, which are presumably the purchase inputs (MY-INFERENCE).
4. Poll seller `GET /status?job_id=`; on completed, recompute hashes with your own identifier and compare to seller's `input_hash/output_hash`.
5. Mismatch or bad result: `POST /purchase/request-refund {network, blockchainIdentifier}`; `POST /purchase/cancel-refund-request`. Seller may `POST /payment/authorize-refund`; else dispute -> admin arbitration; or auto-refund when `refundTime` elapses / no result by `submitResultTime` [SKILL masumi-payments.md "Dispute + Refund"].
- Also: `GET /purchase`, `/purchase/diff/next-action`, `/purchase/resolve-blockchain-identifier`, `/purchase/spending` (name suggests spend reporting; unverified), `/purchase/error-state-recovery`.
- SDKs: `pip-masumi` has a `Purchase` class (create purchase, request refund, cancel refund request) [SDK]. TypeScript: no official SDK found; use axios against MPS (skill examples are TS).
- Via Sokosumi instead: `POST /agents/{id}/jobs` (credits or advanced mode), `POST /jobs/{id}/refund`, job states `refund_pending/dispute_pending` [SKILL sokosumi-api-reference.md].
- MCP: https://github.com/masumi-network/masumi-mcp-server (Python, `uv`) exposes `list_agents, get_agent_input_schema, hire_agent, check_job_status, get_job_full_result`; env `MASUMI_REGISTRY_TOKEN, MASUMI_PAYMENT_TOKEN, MASUMI_NETWORK, MASUMI_REGISTRY_BASE_URL, MASUMI_PAYMENT_BASE_URL` [MCP]. `hire_agent` is the single choke point where an LLM turns into a payment: ideal guard hook.
- Preprod buyer funding: purchasing wallet needs tADA + tUSDM from the dispenser.

## 5. Identity, registry, credentials

- Registration = `POST /registry` on MPS (mints NFT into selling wallet; ~2 ADA + min-UTXO). Body fields case-sensitive: `network, sellingWalletVkey, name, description (<=250), apiBaseUrl (HTTPS), Tags (1-15), ExampleOutputs (1-25), Capability{name,version}, AgentPricing{pricingType Fixed|Free|Dynamic, Pricing[{unit,amount}]}, Author, Legal` [SKILL masumi-payments.md, registry-identity.md]. Hackathon path registers through the admin UI with Dynamic pricing [GUIDE].
- `agentIdentifier` = policyId + assetName (NFT asset id) [SKILL][NFT]. NFT metadata (MIP-002 / CIP-25 `721`) includes name, description, apiBaseUrl, Capability, pricing, Author, Legal, Tags, ExampleOutputs, image, and timing fields; **immutable once confirmed; update only by burn + re-mint** [NFT][SKILL smart-contracts.md].
- Query: Registry Service `https://registry.masumi.network/api/v1` header `token: $REGISTRY_API_KEY`: `POST /registry-entry-search/`, `POST /registry-entry/` (agentIdentifier under `filter.assetIdentifier`), `POST /registry-entry-refresh/`, `GET /capability/`, `GET /payment-information/`; status `Online|Offline|Deregistered|Invalid`; pagination `cursorId` [SKILL masumi-registry-api.md]. [NFT] says registry-entry and payment-information need no auth; the skill says token required: unresolved. Explorer UI: https://www.masumi.network/agent-explorer [dev nav page].
- DIDs/VCs: `did:masumi:...` agent/creator/organization DIDs, W3C VCs (KYB, compliance, technical, reputation) are described in [SKILL registry-identity.md], but the official page says "built-in DID issuance services are planned but not yet implemented"; the Author field can reference a DID document [NFT]. Treat VC/DID as **not usable out of the box**. Reputation on-chain beyond registry status + Sokosumi ratings/execution metrics (agent `metrics.executions/ratings` [SKILL sokosumi-api-reference.md]) was not found.

## 6. Recommended stack and fastest 36h path

- **TypeScript/Node.** Hackathon tooling (Sokosumi CLI, eve, MPS with pnpm/Node 24) is JS; our AgentPay repo is TS/EIP-712. A worker in TS (poll `/coworkers/me/events`, call MPS REST) avoids Python SDK entirely. The Python `masumi` SDK (`pip install masumi`, `masumi init/run/check`) auto-builds all 6 MIP-003 endpoints and payment polling [SDK][SKILL] but targets the classic push path and adds a second language. Choose Python only if we decide to expose a MIP-003 service for other agents to call.
- **Kodosumi: skip.** Python/Ray runtime for scale [SKILL kodosumi-runtime.md]; not required by the hackathon path.
- **Fastest order**: (1) accounts + CLI + Vendor/Coworker (1h); (2) MPS + Postgres up, seed, dispenser funds, register with Dynamic pricing (2-4h, mint wait ~5-15 min; do this FIRST, in parallel with coding); (3) deploy MPS+worker on Railway early, since judges need hosted (2h); (4) free rehearsal Task with `runtime start/complete` (1h); (5) paid Task end to end through collection (3-4h, the riskiest step; schedule early); (6) AgentPay guard layered on top; (7) event workspace connect + approval wait (request early; approval is manual); (8) slides + demo video.
- Keep an idempotency store keyed by Task/event id: judging asks specifically about "not repeating work or charging twice" [SUB].

## 7. Gotchas / failure modes

- Keys: Sokosumi uses `Authorization: Bearer`; MPS/registry use header `token`. Old `X-API-Key` rejected [SKILL]. Preprod and mainnet keys are separate; wrong host gives 401. All MPS paths are singular (`/payment`, `/purchase`, `/registry`) [SKILL api-debug-recipes.md].
- Field names: `submit-result` needs `network, blockchainIdentifier, submitResultHash` (400 otherwise; 401 = wrong token/env). Registry fields are capitalised (`Tags`, `AgentPricing`...). Amounts are strings in smallest unit [SKILL].
- Hash mismatch causes: non-canonical JSON (RFC 8785), wrong identifier, BOM/UTF-8, missing `;` [SKILL].
- Payment stuck: check network, exact amount+asset+address, wait ~20 confirmations (`BLOCK_CONFIRMATIONS_THRESHOLD=20`), Blockfrost key, `GET /payment/diff/next-action`; `payment_pending >5-10 min` usually wrong PAYMENT_UNIT/policy for network [SKILL].
- Collection not happening: `AUTO_WITHDRAW_PAYMENTS=true`, `unlockTime` passed, selling wallet has ADA, service running [SKILL]. Unlock window defaults to 3600s; negotiate a shorter unlock in the signed terms for the demo if allowed (unverified whether terms permit it).
- Local machine must stay awake; the guide says host eve+MPS for judges [T49 demo repo note, GUIDE].
- Preserve `ENCRYPTION_KEY`; suppress seed mnemonic output; do not enter example contract addresses/custom policy IDs in admin [GUIDE].
- Sokosumi: 402 insufficient credits, 403 workspace mismatch / `grant_required`, 409 conflicts, 429 back off exponentially (1s,2s,4s); poll no faster than every 10s [SKILL]. No numeric rate limits documented anywhere.
- Registry/Explorer indexers lag; use `registry-entry-refresh` [SKILL]. Registry marks service `Offline` if `/availability` fails (classic path).
- Docs conflict: `app.sokosumi.com` vs `preprod.sokosumi.com`, port 3001 vs 3012, `Web3CardanoV1` (registry search filter in skill) vs `Web3CardanoV2` (hackathon). Use hackathon values.
